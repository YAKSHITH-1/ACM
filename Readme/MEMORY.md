- [Rate limiting added to auth-backend](rate-limiting.md) — IP+account based limits with exponential backoff for auth routes, moderate limits for public endpoints, looser limits for authenticated actions; thresholds configurable via env vars.
- [Strict input validation added](validation-summary.md) — All endpoints now validate input via express-validator with strict schemas (type, length, format). Auth validators enforce name, email, password complexity, token formats, etc. Event validators enforce ObjectId strings, dates, enum types, phone, etc. Invalid requests are rejected with 400 errors.
- [Dependency audit passed](dependency-audit.md) — Ran `npm audit` and fixed vulnerabilities: updated mongoose from 8.3.2 to 8.24.2 (moderate CVE), body-parser to 1.20.6 (low), brace-expansion to 5.0.9 (high). No remaining vulnerabilities; frontendCSS had none.
- [Error handling hardened](error-handling.md) — Central error middleware now logs full stack traces server‑ed but returns generic messages to clients. Operational errors (duplicate key, cast, validation, JWT) map to safe client‑side messages. Third‑party email API errors are also genericized. No stack traces, file paths, or raw DB details are exposed to users.
- [N+1 query audit passed](Nplus1-audit.md) — Scanned loops and data‑fetching calls; found no instances of per‑item database calls. All related data is batched (e.g., `getMyRegistrations`, `getRegistrations`) or fetched singly per request.
- [Database indexing added](indexing.md) — Added indexes on frequently queried fields: User.verificationCode, User.resetPasswordToken, and compound indexes on EventRegistration (eventId,userId) and (eventId,email). These improve query performance for login, verification, password reset, and registration lookups. Example EXPLAIN before/after shows index usage.
